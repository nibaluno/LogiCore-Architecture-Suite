# LogiCore Architecture Suite

Данный проект представляет собой реализацию логистической системы на языке Java. Основная цель работы — закрепление навыков современного системного проектирования с использованием методологии **GRASP** и шаблонов проектирования **GoF (Creational, Structural, Behavioral)**.

---

## Функциональные возможности системы

1. **Импорт данных:** Чтение информации о доступных грузах и транспортных средствах из внешних источников с поддержкой различных форматов (CSV, JSON, XML).
2. **Расчет логистики:** Вычисление стоимости ($P = \sum c_{i} \cdot m_{i} + r \cdot p_{delivery}$) и времени доставки для партии грузов.
3. **Многовариантный расчет:** Если тип транспорта не определен пользователем, система автоматически рассчитывает и выводит все доступные альтернативы (воздух, земля, вода) для сравнения.
4. **Фильтрация и сортировка:** Возможность гибкой фильтрации результатов (например, по максимальной стоимости или времени) и комбинирования критериев сортировки (например, сортировка по цене, а затем по скорости).
5. **Комбинируемый экспорт:** Сохранение результатов расчета в файл (CSV, JSON) с возможностью прозрачного применения шифрования (Base64/XOR) и архивации (сжатие в `.zip`), которые можно сочетать в любом порядке.

## Использованные паттерны проектирования

### Порождающие шаблоны (Creational GoF)
* **Abstract Factory (Абстрактная фабрика):** Интерфейс `LogisticsFactory` и его реализации (`AirLogisticsFactory`, `LandLogisticsFactory`, `WaterLogisticsFactory`) создают семейства связанных объектов: конкретный тип транспорта (`Transport`) и соответствующий тип сопроводительной накладной (`Waybill`).

### Структурные шаблоны (Structural GoF)
* **Decorator (Декоратор):** Паттерн применен в модуле экспорта данных. Базовые экспортеры (`CsvExporter`, `JsonExporter`) реализуют интерфейс `DataExporter`. Декораторы `CryptoDecorator` и `ZipDecorator` позволяют динамически расширять поведение записи данных (шифровать, упаковывать в ZIP) и свободно комбинировать их между собой.

### Поведенческие шаблоны (Behavioral GoF)
* **Strategy (Стратегия):** 
  * Применен в модуле импорта (`DataParser`) для независимого выбора алгоритма чтения данных (из CSV, JSON или XML).
  * Использован в механизмах сортировки (`Comparator`) и фильтрации (`Predicate`) для гибкой смены правил обработки итоговой выборки результатов перед экспортом.

## Применение принципов GRASP

* **Information Expert (Информационный эксперт):** Вычисления распределены по классам, обладающим необходимыми знаниями. `CargoItem` рассчитывает общую массу и стоимость своей перевозки. `AbstractTransport` вычисляет накладные расходы на движение и время в пути.
* **Creator (Создатель):** Создание доменных моделей возложено на фабрики и парсеры, которые владеют исходными инициализирующими данными.
* **Low Coupling (Слабая связанность) & High Cohesion (Высокое зацепление):** Архитектура разделена на независимые слои. Модели ничего не знают о способах сохранения файлов, а логика расчета изолирована от деталей пользовательского интерфейса.
* **Controller (Контроллер):** Класс `DeliveryService` координирует выполнение основного бизнес-сценария, выступая единым посредником для вычислений.
* **Polymorphism (Полиморфизм):** Изменения в логике работы с файлами, генерации документов и поведении транспорта обрабатываются через полиморфные интерфейсы без использования разветвленных конструкций `if-else`.
* **Pure Fabrication (Чистая синтетика):** Классы для парсинга данных (`CsvParser`) и форматирования файлов экспорта не представляют сущности реального мира логистики, а служат целям сохранения слабой связанности.
* **Protected Variations (Защищенные изменения):** Контракты интерфейсов (`Transport`, `Waybill`, `DataExporter`, `DataParser`) защищают систему от нестабильности внешних интеграций и изменений форматов.

## Структура проекта

```text
src/main/java/org/example/
│
├── domain/                         # Доменные модели (бизнес-сущности)
│   ├── cargo/                      # Cargo.java, CargoItem.java
│   ├── document/                   # Waybill.java, AirWaybill.java, LandWaybill.java, WaterWaybill.java
│   ├── transport/                  # Transport.java, AbstractTransport.java, AirTransport.java, ...
│   └── dto/                        # DTO для результатов расчетов (DeliveryResult.java)
│
├── factories/                      # Реализация паттерна Абстрактная Фабрика
│   ├── LogisticsFactory.java
│   ├── AirLogisticsFactory.java
│   ├── LandLogisticsFactory.java
│   └── WaterLogisticsFactory.java
│
├── parsers/                        # Модуль импорта и чтения файлов (Паттерн Стратегия)
│   ├── DataParser.java
│   └── CsvParser.java (также JsonParser, XmlParser)
│
├── export/                         # Комбинируемый экспорт данных (Паттерн Декоратор)
│   ├── DataExporter.java           # Интерфейс компонента
│   ├── CsvExporter.java            # Конкретные компоненты
│   ├── JsonExporter.java
│   ├── ExporterDecorator.java      # Базовый декоратор
│   ├── CryptoDecorator.java        # Декоратор шифрования
│   └── ZipDecorator.java           # Декоратор сжатия
│
├── service/                        # Сервисный слой (Контроллеры)
│   └── DeliveryService.java
│
└── Main.java                       # Точка входа в приложение
```

## Описание формата входных данных (`logistic.csv`)

Входной файл должен находиться в каталоге ресурсов проекта (`src/main/resources/logistic.csv`). Данные разделены точкой с запятой (`;`). Пустые значения для неиспользуемых полей (например, расход топлива для груза) заполняются нулями во избежание ошибок разбора чисел:

```csv
Тип записи;Наименование;Масса_ед_кг;Стоимость_перевозки_за_кг;Расход_на_км;Скорость_км_ч
cargo;Электроника;1.5;50;0;0
cargo;Одежда;0.8;20;0;0
transport;Грузовик (Земля);0;0;15.0;80
transport;Самолет (Воздух);0;0;150.0;850
```

## Сборка и запуск проекта

Сборка осуществляется стандартными средствами Maven:

1. Очистка и компиляция исходного кода:
   ```bash
   mvn clean compile
   ```
2. Создание исполняемого JAR-архива:
   ```bash
   mvn package
   ```
3. Запуск приложения:
   ```bash
   java -cp target/classes org.example.Main
   ```
